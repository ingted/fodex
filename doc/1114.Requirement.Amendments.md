# 1114 任務規格修訂

## 2026-11-14：cache key 禁止尾端空白

使用者回覆：**「改規格，禁止 key 尾端空白」**。

此決策補充原任務 §5.1 的 key 規則；其餘條件不變：

- key 長度1～256個UTF-16字元、Ordinal／大小寫有別、不含NUL。
- 最後一個字元若 `Char.IsWhiteSpace` 為真即拒絕（含一般空格、tab、換行及Unicode空白）；不自動Trim、不改寫使用者key。
- Create／Read／Update／Delete一致驗證，不能透過read/delete繞過而命中另一個key。
- SQL保留BIN2及原 `PK(StorageId,Key)`，不新增KeyBytes。

原因：本機SQL實測 `N'k' COLLATE Latin1_General_100_BIN2 = N'k ' COLLATE Latin1_General_100_BIN2` 為真，與原本任意尾空白Ordinal key語意不同。此修訂由使用者明確選定，沒有自行更改KV namespace／trim策略。原人類任務文件保持原樣，由本修訂紀錄補充。
