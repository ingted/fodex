# 1114 任務規格修訂

## 2026-11-14：cache key 禁止尾端空白

使用者回覆：**「改規格，禁止 key 尾端空白」**。

此決策補充原任務 §5.1 的 key 規則；其餘條件不變：

- key 長度1～256個UTF-16字元、Ordinal／大小寫有別、不含NUL。
- 最後一個字元若 `Char.IsWhiteSpace` 為真即拒絕（含一般空格、tab、換行及Unicode空白）；不自動Trim、不改寫使用者key。
- Create／Read／Update／Delete一致驗證，不能透過read/delete繞過而命中另一個key。
- SQL保留BIN2及原 `PK(StorageId,Key)`，不新增KeyBytes。

原因：本機SQL實測 `N'k' COLLATE Latin1_General_100_BIN2 = N'k ' COLLATE Latin1_General_100_BIN2` 為真，與原本任意尾空白Ordinal key語意不同。此修訂由使用者明確選定，沒有自行更改KV namespace／trim策略。原人類任務文件保持原樣，由本修訂紀錄補充。

## AGY 首次生成尚無 SID 時的 model／effort 變更

使用者已選定：**先拒絕變更，保留正在執行的工作；等真正 SID 出現後可重試**。

AGY 第一次生成的成功 terminal 才回傳實際 SID。owner 在執行 cancel／apply／persist 前檢查 active 與 typed SID；active 但沒有 SID 時，拒絕提案，不取消、不另建 session、不偽造或沿用其他 provider 的 SID，也不在背景等待後偷偷套用。idle 且尚未開始第一輪者仍可更新下一輪設定。

## 舊 LINE root 遷移的 service 接口

增加 Akka `native_info` 唯讀查證操作（不是額外 native MCP tool）。原因：舊 LINE 名冊沒有 provider/argv，直接使用現行 AGY defaults 建立舊 Codex wrapper 會留下錯誤設定；讓 LINE 讀 Fodex 私有 SQL schema 又違反責任邊界。因此由 service 恢復 graph 並提供驗證結果，LINE 只維護自己的名冊。查詢不生成 native、不改 SID／generation；遇到可證明的 legacy typed-binding migration，仍沿用既有 verifier 保存型別證據，不猜 provider。
