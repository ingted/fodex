## P2-2：SQL authority、cache owner 與控制通道

新增 ReActDataStoreV403、SharedCacheFodexFunV100、ParticipantOperationsFodexFunV405、ReActLoopHandlerV405、ReActTraceV302，舊版來源保留。另新增 NativeCommandFodexFunV100，以既有 Proc Supervisor 1.572.12 執行有限時、有限輸出的管理命令；非同步 ROP helper 放回既有 FodexFunBinding。

- cache 的 KV／journal 同一 transaction；兩側任一失敗全部 rollback。operationId 重試回原收據，不同 payload 拒絕。SQL 成功後才換 graph。
- 唯一 owner 持有 SQL session lease（不回連線池），重複 owner 被拒；停止後可由新 owner 接手。checkpoint 加完整 tail 還原，並修復 KV 投影；不套一小時視窗。
- cache owner 是沒有 native 的 control ReActLoop。普通 loop 只轉送同一 JSON request，不新增另一份 KV、不佔 participant N、不產生 user/model event。
- 普通 loop 代理送件後即釋放 mailbox；SQL trigger 延遲三秒時仍能讀普通 graph。跨兩個真 Akka node 可往返完整 1MiB、含 JSON 跳脫字元的 value。
- model pair 目前只完成 typed request/reply 與 ROP wire，正確區分 requested wrapper 和回傳 native leaf；尚未宣稱 model catalog／套用政策已完成。

驗證：Debug build 成功；cache 16/16、participant wire 3/3。新增五份 FodexFun 測試（SharedCache、ParticipantOperations405、Trace302、Handler405、NativeCommand）均可獨立 FSI 執行且 exit=0。SQL403 已另通過7/7與獨立FSI；NativeCommand已另通過2/2。VS adapter 本次 selector 實際選取31項，全數通過；整輪回歸尚待本階段完成後驗證。
