## 正式觀察的未解阻塞：RN 同對話 FIFO

AGY 文字在 23:14:44 發出，Codex 文字在 23:14:55 發出；但 SQL 的第二批 FirstAtUtc 是 15:15:52.490Z，直到第一批完成後才接納。這不是只看模型速度作推論：RN source `LineActorDispatch.createAccountDispatchResolver` 以 account＋processor＋conversation 建立可靠投遞 lane；其 `WorkerTests` 明確驗證同一 conversation 的後件必須等前件 terminal，其他 conversation 才能並行。

因此，v3 ingress 即使不 await generation，後件仍在上游 producer／consumer lane 等候，尚未進入 v3 的 SQL batch；只改三秒 timer 無法解決。同一對話的圖文三秒合併與生成中控制尚不能宣告正式通過。需為 v3 分離 admission 與結果交付、維持非 v3 provider 原 FIFO；已向使用者提出 RN 套件修改範圍確認，未擅自改動或升級固定版本套件。
