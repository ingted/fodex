我們的 Harness:

H1. 禁止自作聰明
H2. 禁止重新發明輪子

=> 專案有的資源就好好利用，像是 PostBuildEvent.ps1 都處理了 nuget push ，禁止你再手動下 nuget push 

H3. 如果手邊沒有輪子拜託可以先問人類或者其他 agent

=> 像是 nuget push 這種很基本的操作，人類或成熟專案肯定有工具，請先跪求人類或其他 agent

H4. 碰到異常應該是處理 root cause，如果在忙，應該向人類請求增派 agent 修復 root cause，而不是透過 workaround (甚至長期 workaround)

=> 請勿掩耳盜鈴

H5. 當你執行正式的 A 隱含執行正式的 B 時，這就是一個 formal 的行為，請勿自己跳過 A 去執行 B

=> 當你在一個 context 情境當中想幹 B 的時候，請先 COT 生成思考：這樣做有沒有更佳作法？是否能找到既有的更佳流程化的作法，例如: trigger A，也許更符合 SOP

H6. 不要把與專案沒有直接關係的 `暫存 / 實驗性質...(之類)` 的 `程式碼 / artifacts / (網路上下載的)工具...(等等)` 放在專案資料夾

H7. 請遵循第一性原理執行任務，但是要以 `人類心智能力能負荷` 的 `設計 / 架構 / 實作` 交付

=> 永遠先 COT 生成: 人類這個 `類比/比喻/舉例/說明` 是什麼意思? 人類有沒有想引申什麼? 原始目的為何? 當下的情境目標是否應該要調整? 如何在當下的情境達成目標?

以下為專案可用資源：

R1. E:\deletable: 暫存資料夾(不定期清空，請勿放置重要資料)
R2. E:\temp_worktree: worktree 資料夾 (磁碟空間不足時清空)

專案目錄禁止放置 agent 個人開發用之 暫存檔/設定檔/實驗腳本/實驗性質專案，此類檔案請放在 R1. R2.
