    148 +## 3. 編號、身分與 FGL 的必要規則
    149 +
    150 +### 3.1 三種數字／名稱不能混用
    151 +
    152 +- `/subagent(N)` 的 N：希望備妥的 sub 數量。
    153 +- `/stop sub(N)` 的 N：`/list_participant` 顯示的穩定控制編號。
    154 +- `hub_order(who, instruct)` 的 who：owner 範圍內的派工名稱，例如 `sub-1`；不是 Codex sid，也不一定等於顯示編號。
    155 +
    156 +建議清楚顯示 name／who 與 N 的對照，保持既有 who 語意，不把模型輸出的名字當成 lifecycle authority。
    157 +
    158 +### 3.2 唯一性的範圍與配置權
    159 +
    160 +建議保證「同一 root wrapper 所屬 execution tree」內，跨 local／remote 的 N 唯一。
    161 +不是宣稱不同使用者、不同 root wrapper 的裸整數也全球唯一；完整操作識別包含 root scope。
    162 +
    163 +```text
    164 +(root wrapper session, N)
    165 +    -> 完整 ReActParticipant key
    166 +    -> 當前 owner／binding
    167 +```
    168 +
    169 +必要不變量：
    170 +
    171 +1. 由 root ReActLoopHandler 統一核配 N；遠端 owner 向它註冊，不自行從 1 開始另配全樹編號。
    172 +2. N 與完整 endpoint、parent、who 的對應須在暴露為可派工前 durable commit；不能只存在 console array。
    173 +3. 同一身分 restart／rebind 保留 N；actor address 可更新。新 logical participant 取得新 N。
    174 +4. 已配置的 N 不因刪除、失敗、排序、filter、重連或重啟被重用；停止後也不重編其他行。
    175 +5. SQL 對 `(root,N)` 與 `(root,完整endpoint)` 建唯一性保護；單一 owner actor 負責順序，DB 保護不能代替 owner 協調。
    176 +6. root 不可用時，不能由另一節點臨時配號或 fallback 到本機同號 actor。
    177 +7. 舊的 session-local 1／2 可以保留；新 COT／raw sub 必須透過同一身分配置流程預留 endpoint，消除 `3+index` 與 `max+1` 各自配號的競爭。
    178 +8. IP hint、actor path、process PID 都不是替換 logical identity 的理由。不能因 remote rebind 就用新 IP 重組 key，把原 participant 變成另一個人。
    179 +
    180 +這是一個 root writer 的模型，不在 M017 引入分散式 consensus、跨 root 全域計數器或新 database framework。

    182 +### 3.3 `/list_participant` 的欄位
    183 +
    184 +| 欄位 | 權威來源與顯示規則 |

    186 +| N | root 統一配置的持久控制編號；不是 `Seq.mapi` 產生的行號 |

    188 +| sid | wrapper 顯示 `WrapperSessionId`；native 顯示實際 Codex session id；新 exec 尚未發出 thread.started 時顯示未建立，不能捏造 GUID |
    189 +| actor address | owner 回報的當前完整 actor path；raw exec 顯示管理該 who 的 worker actor，不冒充有一個不存在的 Native IAgent |
    190 +| parent sid | immediate parent wrapper 的 sid；root 為 None。內部關聯仍用完整 parent endpoint，不能只用顯示字串 join |
    191 +| kind／status（建議補充） | wrapper／native／raw exec／COT；以及 starting／idle／running／stopped／unreachable 等，避免只看到地址就以為存活 |
    192 +
    193 +列表須包含尚未產生輸出的節點，以及已停止但仍屬這棵樹的身分。
    194 +finished／removed COT 可另標示歷史狀態，不抹除其 N 與歷史關聯。
    195 +未知或遠端離線時，顯示 last-known 資料與 freshness；不能自動 Acquire／Start 來「查資料」。
    196 +`AcquireParticipant` 有建立副作用，不適合作為純清單的遞迴探索方法。
    197 +
    198 +以下只是編號示意，不是新的硬編碼：
    199 +
    200 +```text
    201 +N=1 root wrapper       sid=W0       parent=None
    202 +├─ N=2 main native     sid=C0       parent=Some W0
    203 +├─ N=3 sub-1 wrapper   sid=W1       parent=Some W0
    204 +│  └─ N=4 main native  sid=C1       parent=Some W1
    205 +├─ N=5 sub-2 wrapper   sid=W2       parent=Some W0

    207 +└─ N=7 explicit COT    sid=C3       parent=Some W0

    213 +### 3.4 FGL 落實方式：需要明確選擇，不能偷偷在 UI 補 registry
    214 +
    215 +目前 Contract 明確把 committed dataflow graph 與 live IAgent 分開，node label 是 `unit`。
    216 +若完全不動 Contract，又要求 ownership／編號本身以 FGL 維護，建議：
    217 +
    218 +**方案 A：同一 ReActLoopHandler 擁有 implementation-only execution topology FGL。**
    219 +
    220 +- key 沿用完整 logical participant；label 放上節所需的純 metadata；parent→child 是明確 ownership edge。

    222 +- 既有 live binding 繼續保存真正 IAgent；raw exec 綁 owner worker。可保存 metadata 不包含 CLR object／callback／Process。
    223 +- `/list` 查 topology；顯示流／匯出查 dataflow。兩者由相同 owner 管理、相同 logical key 關聯。
    224 +- metadata 使用既有 SQL Server 持久化；恢復只恢復資料，不因 replay 自動重新派工。
    225 +
    226 +這裡有兩種不同關係：ownership 與 message flow；不是再拆一個 memory engine，也不是另一份輸出 queue。
    227 +代價是多一個明確的 topology 投影與其 persistence。這個結構變動需要先討論，不默認已批准。
    228 +
    229 +**方案 B：如果你要的是「同一張現有 graph 同時承載 ownership 與 dataflow」。**
    230 +
    231 +就必須討論修改 node label、ownership edge 的表示方式，以及 codec／DB／snapshot／舊資料讀取相容性。
    232 +只把 `unit` 換成 metadata 並不會自動解決 ownership edges、孤立節點保存與跨 graph 合併問題。
    233 +這會跨進 Contract 變更，本輪不做，也不以 fake Message／JSON 字串塞入普通訊息來繞過型別。
    234 +
    235 +在「Contract 保持凍結」的前提下，我傾向 A；若不接受額外 topology FGL，必須先選定 B 的最小範圍再開發。
