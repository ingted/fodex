• 目前是第一種：sub wrapper 建立在同一個 .NET process、同一個 ActorSystem，透過它的 IAgent.Send 接收派工。

  建立順序是：

  1. coordinator 從 registry 取得 wrapper factory。
  2. factory 呼叫 WrapperAgent.create，以 spawn node 建立 actor，取得 IActorRef。
  3. 用 Wrapper actorRef 建立 IAgent，再透過 loop.UpsertParticipant 登記。

  見 建立 sub wrapper (/F:/fodex/Fodex.Supervisor/SubagentCoordinatorV300.fsx:95)、建立 wrapper actor (/F:/fodex/Fodex.Supervisor/WrapperAgentV300.fsx:106)。

  送 prompt 的路徑是：

  main native 呼叫 hub_order(who, instruction)
    → hub／coordinator 找到 sub wrapper 的 IAgent
    → subWrapper.Send(WrapperOrder(...))
    → sub wrapper actor 排入工作
    → ReActLoop 路由給該 wrapper 的 main native
    → native 執行 Codex exec／resume

  目前 Send 裡包的是 WrapperOrder，包含 instruction、causedBy、取消 token 與回覆 callback。見 派送位置 (/F:/fodex/Fodex.Supervisor/
  SubagentCoordinatorV300.fsx:73)。

  Proc Supervisor 不會再啟動另一個 Proc Supervisor console application。 目前直接使用 NuGet library，在既有 ActorSystem 建立 ProcRegistryActor／
  ProcNodeActor，由它們啟動及管理外部 Codex CLI 程序。見 Proc Supervisor 建立與啟動 (/F:/fodex/Fodex.Supervisor/ProcSupervisorV201.fsx:13)。

  所以，同一個程序裡可以有多個 wrapper/native actor；各 native 使用的 Codex CLI 才是另外的 OS process。

  啟動時，在 defaultArgumentsText 設定預設模式：

  --subagent-mode wrappers

  或：

  --subagent-mode raw

  /subagent(3, wrapper)
  /subagent(2, raw)
  /subagent(4)
