## 2. 最少 N、既有身份與差異派工

- 按可並行、可獨立驗收且 allowedPaths 可協調的工作選最少 N。簡單工作可由 main 單獨完成，或 main＋一個 worker；若目前授權是 main-only-dispatch，main 仍只能派工，不能因工作小就自行實作。
- 只有實際存在的 who 可被派工。**1+N 的 N 是 worker 數量；本案 participant 清單中的 N=9/10/11 是使用者控制號碼，不是人數。** 兩者不可混用，也不能從控制號碼推導 who、SID 或模型 ID；只用使用者已指定且可核對的映射，不自行猜測。缺少指定 participant／可 resume SID 時記錄該派工的 blocker，不擅自建立 wrapper/process/新 participant、換 sid 或改用他人身份。
- 維持 session resume，保留 who→SID→owner 的可核對映射。長 context 應先依核准機制壓縮，不把換 SID 當透明節省手段。
- 共用契約只維護一個版本化權威引用；首次讀取與已讀版本狀態按各 SID 追蹤，不能因 main 已讀就視同所有 sub 已讀。契約變更明列版本與影響，不把每輪全文貼給所有人。每輪 payload 只帶實際差異、owner、allowedPaths、dependencies、AC、baseline 與 evidence 需求。
- 按風險指定專項與交叉審查；不預設每位 worker 重讀整案。共享檔案或 Git index 有競爭時，先明確 owner，不用更多 N 放大衝突。
- **本案 sub-4/5/6 的現行 transport**：root 派工／receive 使用已批准的 compiled HTTP client，不擅換 MCP／FSI。未來通用 harness 則依每批／participant 的使用者指定介面，不把本案 client 當成所有情境的硬規則；仍不得為省 token 擅換介面或新建 wrapper/process。資料 schema 只是記錄模型，不代表可自行新增 wire 參數或改 API。文件 QA 的既有 FSI scanner 與派工入口是不同用途。

## 3. 先驗正式最小真鏈，再擴並行

先固定共用契約、必要版本與權限，再由已授權 owner 打通正式入口的最小真鏈及必要依賴。compile、module reflection、verify-only、registration ready 或測試專用 preload 都不能代替 AC 要求的真 runtime。

測試者可先依契約獨立準備 fixture、oracle 與隔離資源；文件先建必要骨架，終版在必需結果收齊後集中整理。不要在入口／依賴尚未釐清時，讓多位 worker 各自把假設擴寫成已驗收設計。

這個先後關係仍受 §4 的同輪硬邊界約束。例如同輪已授權的開發入口檢查、測試準備與文件骨架可以並行；未收齊該輪所有 orderId，不能因某份 ready 提早發下一輪驗收單。ready 卡是狀態，不是額外派工授權。

單一 git index owner 統一必要收尾；其他 owner 只交精確 changedPaths、結果與證據。文件收尾不應為記錄自己的每次 commit/push 無限產生 metadata commits；可依工作區／任務授權，將最後 readback 記到指定文件。

## 4. 一組小 schema 與收件硬邊界

以下是一組記錄範例，欄位值是占位符，不是建立 participant／SID 或執行真派工的命令。orderId 依使用者指定 transport／正式 client 契約取得或核定；若提交後才回傳 ID，就在回傳時補入 ledger，不假設 API 接受自訂 ID。result 必須透過 orderId／round envelope 關聯，不依到達順序猜測。

```json
{
  "order": {
    "round": "R01",
    "orderId": "<designated-transport-returned-id>",
    "who": "<existing-who>",
    "contractVersion": "<immutable-contract-version>",
    "baseline": "<source-and-runtime-fingerprint-ref>",
    "allowedPaths": ["<exact-owned-path>"],
    "dependencies": ["<ready-state-at-matching-fingerprint>"],
    "AC": ["<specific-behavior-and-verification-scope>"],
    "budgetHint": "advisory only; no paid hard limit authorized"
  },
  "result": {
    "orderId": "<same-order-id>",
    "status": "complete",
    "changedPaths": ["<exact-owned-path>"],
    "testedFingerprint": "<immutable-tested-inputs-ref>",
    "results": {"executed": 1, "passed": 1, "skipped": 0, "scope": "<verified-scope>"},
    "defects": [],
    "evidenceRefs": ["<canonical-immutable-evidence-ref>"],
    "nextOwner": null
  }
}
```

`status` 必須區分 complete、partial、failed、blocked 等實況；數量只填已執行且可核對的結果。`budgetHint` 只提示工作量與摘要需求，未經使用者授權不設定付費硬上限。完整 stdout、history 或大 JSON 放 evidenceRefs 指向的核准位置，結果回覆只保留必要欄位。

**目前硬邊界：同輪先全部送完，再持續 receive，直到所有已提交 orderId 都收到，才進下一輪。** harness 保存 submitted/received/outstanding ledger，部分 receive 不等於完成，也不重送已提交單。取消等待、本地 timeout 或顯示 ready 都不能補成收到結果。

短共享 ready 狀態只放 owner、契約／fingerprint、狀態與證據引用；由權威 owner 更新，證據本身不可變並可核 hash。模型只讀目前小狀態與相關證據，不反覆全文讀 append 長 history。

DAG、跨輪穿插派工或以早到結果啟動下一輪，只能列為**未來另行授權選項**；本設計不據此變更現行收件規則。

## 5. runtime 等待、長 exec 與不確定交付

等待、heartbeat、ledger 對帳與簡單進度顯示，盡量交由已核准 runtime 的確定性機制處理，避免為空輪詢喚醒模型。若該批／participant 指定的 transport 沒有所需能力，先提案與測量，再按現有授權改 harness；不能擅換 MCP／FSI、臨時新建 wrapper/process 或借用其他 SID。

必要主控進度回報仍遵守上層規則；不能以省 token 關掉規定回報，或把所有安靜時間都視為零成本／固定 token 成本。

- queued／Tell、participant online 與 native 開始 ACK 分開；最終完成另須對應回合／callback／receipt 證據。不得把其中一種當成另一種。
- 長 exec 回傳 session id 後保留該 session，依工具契約續接，不因首次 yield 重啟第二份程序。
- receive timeout／取消 receive 只影響等候；取消 order 是另一個需授權、需核對 acknowledgement／terminal result 的動作，不能互相代替。
- disconnect 可能造成 delivery-uncertain。先依 orderId 與既有 ledger／正式 client 能力對帳，不能盲重送。若能力不足，保留不確定狀態並回報 blocker，不假造結果或清空 outstanding。
- 只有契約允許且已正式收到的 terminal result/ack 才能計入收件。本地取消等待不解除「收齊本輪」硬邊界；變更此規則須另有明確授權。

## 6. context 水位、壓縮與 IO

soft/hard 水位必須依目前可核對的可用 context、輸出預留量與工具增量需求設定；不能把分析中觀察到的 475000 泛化成可用上限。單次 input 才是當下負荷指標，累計 input 不是 context 水位或記憶體。

**待校準提案，不是已配置值**：若 `Cusable`、預留 output `Rout`、尚未注入的必要工具／結果增量 `Rfuture` 都可實測，可先以 `H = Cusable - Rout - Rfuture` 檢查可用 hard 輸入界線，再由實測不確定餘量 `M` 設 `S = H - M`。已在目前 input 內的工具定義／歷史不可再重複扣算。這些變數與公式需校準，不是付費硬上限。

上限或預留量未知時，不猜數值／百分比；先縮小新增注入、使用核准摘要／壓縮，必要時回報缺口，不擅換 SID。soft 水位可觸發整理，hard 界線不得以刪除未收單、丟證據或改授權來通過。

壓縮必須保留：owner/who/SID 映射、order ledger、未完成與交付不確定單、baseline hashes、契約與決策、失敗／例外、evidenceRefs、目前權限與下一步。壓縮是表示法改變，不是新授權、收件完成或 SID 遷移。完整記錄保留外部，但不每輪重新注入。

寫摘要或引用外部檔只避免新增膨脹，不會自行刪去已載入 history；真正縮短既有 context，須由現有且已授權的 compaction/truncation 機制執行並核對用量，不擅換 SID。既有前綴仍可能被 API 重送並計入 cached input；「不重複注入」是指不再附上同段副本。契約首次讀取／版本狀態按各 SID 追蹤，不把 main 的已讀狀態套給所有 sub。

Read-CodexStdout 在同一 session **不可並行**。stdout、stderr、合計都必須各自嚴格小於 **20KB**，摘要還應明顯更短；以 bytes 而非中文字數估算。首次即用 exact paths、metadata、rg、JSON selector 或有界片段。超限先取 metadata／必要 selector，不能全文讀超限 raw，再靠模型摘要。

## 7. fingerprint、覆蓋與按變更重測

fingerprint 至少按任務保留以下必要輸入；缺項要明示，不能只有 Git commit：

- source repo／版本與實際工作檔 hashes，包含必要 shared dirty 及跨 repo helper。
- 真正載入的 binary path/version/hash、必要非敏感 config／dependency 版本或內容 hash；不只看檔案存在、mtime 或相同 assembly version。
- testcase source、正式／診斷入口、有效 args、必要 feature flags／環境與資料／fixture 識別。秘密只用安全 reference／版本或核准加密檔的 checksum；不把秘密值或可猜測秘密的 digest 當作通用安全記錄，也不為計算 fingerprint 把 secret 載入 context。
- AC、隔離資源、reply sink 與驗證層級，必要時含 seed／clock 與 state authority。

輸入沒變且覆蓋足夠時引用已有結果，不為每輪儀式重跑。wording 變更不自動觸發整套 native/E2E；先做影響分析與相應小 scope 驗證。若 source hash 變了，不能把舊結果改標成新 fingerprint：應標清新測範圍、重用的舊 evidence 及未變的 runtime 子集合。上層明定必跑的 checks 仍須執行。

失敗、版本漂移或覆蓋缺口才重測相應 scope；失敗原證據保留。最終正式入口須直接可跑，測試專用 bootstrap／額外 preload 成功不能冒稱產品修復；若 unit 有執行條件也要明列，不能標成原入口直接通過。

unit、synthetic backend＋真 native、live service、real LINE、clean checkout／獨立 artifact 是不同證明範圍。正常 host ready 不等於 LINE delivery、公開媒體或 deadline 通過；同版 binary 與 dirty source 的 workspace 成功，也不等於完整交付閉包可重現。

## 8. 記錄、Git 與不可突破的邊界

必要 log、DevLog、敏感掃描、commit/push 仍依當前工作區與使用者授權執行；實際 pre-work／Operations 時間不可事後偽造。harness 可按授權一次產生 changedPaths、hash、結果與掃描的小摘要，完整紀錄外置，不能靠省略合規步驟達成節省。

appendable 文件用 append-only/prefix 規則監控，不當成 readonly 凍結 evidence。凍結前先停止 writer；活寫輸出避免放進其自身 readonly snapshot。若 verifier 與明確授權衝突，保留 raw FAIL、scope 與例外依據，按授權修 verifier／補必要測試或記精確例外；不弱化 verifier、刪 baseline、換 scope 掩蓋失敗或偽造 PASS。

單一 index owner 在 commit 前核 staged list 與精確 owned paths；已有他人 staged 不混提交，也不自行 reset/restore。既有 dirty、秘密不得因 token 目標被覆蓋、輸出或擅自納入交付；政策拒刪不換方法繞過。當前任務明確禁止 commit/push 時照辦，不把未來守則當授權。

## 9. 衡量：完整拓撲與合法可比基線

量 root＋全部 workers，不只主控或有成果的 worker；包含 bootstrap、交接、取消、重試、compaction 的實際模型用量。按原始 provider schema 分開 cached/uncached/input/output/reasoning：若 cached 已含於 input、reasoning 已含於 output，就不加兩次。cumulative delta 與非單調 reset 按[分析的統計原則](00016.token.usage.analysis.md)處理。

每個試行應報：

| 指標 | 記錄原則 |
|---|---|
| token | root及所有worker分列與合計；單次input和累計分開，未知reasoning子量不補造 |
| cache | 記cold/warm／可比條件與原始欄位定義；不能只看cache% |
| 延遲 | 區分整案、同輪收齊、等待與實際request→reply；缺timestamp就標未知 |
| 重跑／缺陷 | 記重試原因、返工、漏測、最終AC品質，不以少跑檢查製造便宜結果 |
| 主控空回合 | 定義為無新資料／決策／必要回報而由輪詢喚醒的模型回合；必要回報不冒稱可刪空轉 |
| context水位 | 各session實測單次負荷、可用量與預留量；未收集峰值不拿last input替代 |

以同 AC、版本、品質、權限與可比較 cache 條件，多次對照合法的單 agent 基線與最少 N。若 main-only-dispatch 限制仍在，不能讓 main 越權實作來做便宜基線；main＋1 worker 的拓撲仍須計 main 成本，不能假稱真正零主控的單 agent。沒有可比且獲准的基線就不作因果節省結論。

沒有價格就不算金額。單價、cache、環境或任務不同時先揭露不可比性，不能只增加 N 或看高 cache hit 宣稱成功。

## 10. 小步試行、驗收與停止條件

1. **現在：只交文件守則。** 尚未改 harness、安裝 skill 或啟用節省策略，沒有可宣稱已套用的節省百分比。
2. **先核對試行 scope／現有權限。** 已授權範圍不重問，不因省 token 守則另加審批 gate；缺少必要授權才補足。從已核准入口記錄完整 ledger、usage與fingerprint；不自行建立participant／換sid／付費硬上限。本次歷史snapshot不包含目前文件任務，這裡不追算。
3. **一次試一個小變更。** 可先比較契約版本引用、差異payload、短result卡或確定性等待的效果；保留同輪收齊規則，先校準水位與可觀測性，再改harness。DAG／跨輪策略仍須另行授權。
4. **多次匹配比較再決定啟用。** 試行樣本數、成本／延遲／品質的容許界限均事前協定並待校準，不在本文件臆設數值或金額。報差異與變異，無穩定證據就記未證明，不宣稱固定節省率。

驗收需同時成立：所有submitted orderId按本輪硬邊界收齊；owner/SID/契約與必要fingerprint一致；同AC品質及必要正式入口checks足夠；沒有新增秘密／dirty／政策越界；用量能對帳root與全部workers。token／延遲改善須在可比條件及事前同意的品質界限內支持，而不是靠省略驗證。

停止條件按受影響 scope 處理，不把比較失效擴張為全案停工：

- usage 缺口／cache 不可比：停止 token 比較、節省結論或該優化試驗，不自動停原本獨立且已授權的開發。
- fingerprint 漂移：只重驗受影響 scope，舊證據不冒稱涵蓋新輸入；不因此全面停工。
- 他人 staged：只停止相關 Git 寫入，不動其 index；其他獨立授權工作可繼續。
- 交付不確定、遺失／重複單、SID／權限／秘密／ownership／政策問題：停止受影響的派工、寫入或副作用動作，保留 ledger，依現有授權安全 receive／對帳。獨立授權工作可繼續，除非使用者另有硬限制。

上述分 scope 處理不取消既有單、不丟棄收件，也不解除同輪全收齊規則；未收齊全部 orderId，仍不能提早發下一輪。
