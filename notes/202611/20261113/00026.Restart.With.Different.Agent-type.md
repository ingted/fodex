## 0. 決策摘要

這不是把 Codex SID 改名後交給 AGY resume，也不是 /wrapper_compact 的摘要流程。

1. 先從持久化資料還原可驗證的 FGL graph；沒有正確 graph，不能啟動替代 participant。
2. 邏輯 participant 的 N、who、parent、wrapper SID 保留。agent-type 改變時，新建 native session／SID。
3. 以 graph 重建本次 handover 視窗：依 StreamId 倒序讀取、逐筆 prepend，約達 60KiB 即停止，因此文件內容仍是正序。
4. 必須包含所選範圍內 participant 的輸入／輸出與關係，不只 root wrapper 印給使用者的最後答案。
5. StdOut、StdErr、原始 process IO 不進 handover.md，不計入 60KiB 預算。
6. 新 native 的第一筆輸入必須是 handover bootstrap；一般使用者 prompt／hub order 必須等 handover 完成後才送達。
7. bootstrap 成功、取得真實新 SID、graph／SQL 原子切換成功後，才能宣告新的 participant ready。
8. 不使用 COT participant，不呼叫 LLM 摘要，不自動 prune 原 graph 或刪 SQL 歷史。
9. main、sub wrapper 的 main native、raw sub 都使用同一個 ReActLoop 重啟操作；console、MCP、LINE 不各寫一套。

使用者已確認：保留 N、新 SID、graph 保留前後 session 關聯。原先「完整 context」的無界歷史要求，已收斂為最新約 60KiB 的 graph context。完整性指選定視窗的資料與來源可解讀，不宣稱把舊模型不可觀測的全部內部 context 原樣搬到另一家 provider。

60KiB 在本設計只限制 handover 視窗；不更改既有 operational graph 的最近一小時／手動 compact 保留政策。若要同時裁切 live graph，是另一個需要明確確認的行為。

### 1.3 現有 graph recovery


不是只保存 edge，亦不是重新建立 IActorRef／Process。ReActDataStoreV401 提供 async checkpoint／事件 SQL 操作。

- WrapperAgentV407.beginReplacement 目前 reserve 新 main N，再切 Main 關係。這套舊 replacement 不能直接拿來實作「跨 provider 保留 N」。
- 一般 observation 的 SID 不變保護仍須保留；只准本文件的、經驗證的 transition 更換 SID。
- 同一 root 內的 sub wrapper 使用既有 root loop／全域 N；不能額外建一張與主 graph 無關的 sub context graph。

## 2. 名詞與不變量

### 2.1 邏輯身分與原生 session 分開

~~~text
Logical participant = (root scope, N, participant wrapper/session key)
Native binding       = (agent-type, native SID, session generation)
Physical incarnation = actor ref / address / process / launch ID
~~~

- 邏輯 N 不變，who 與 parent 關係不變。
- agy ↔ codex：generation 增加，SID 必須來自新 provider 的實際啟動結果。
- 同 provider 的普通 actor／process 重綁：仍以原生 resume 為優先，SID 不變，不冒充跨 provider handover。
- 同 provider 的 SID 已損毀：若明確要求 fresh replacement，可重用同一 handover 機制，但不得靜默降級成新 session。
- physical launch ID 與 session generation 不同；一次 exec＋resume 可以有多個 process launch，但仍是同一 generation。

### 2.2 main／sub 的精確含義

| 操作對象 | 真正替換的執行者 | 保持不變 |
|---|---|---|
| root wrapper 的 main | 該 wrapper 的當前 native N | root wrapper SID／actor facade、native N、Main 關係 |
| sub wrapper | sub wrapper 的當前 main native N | sub wrapper N／SID／who／parent，以及其 main native N |
| raw sub | 該 raw native N | raw N／who／parent／hub 路由 |
| 遠端 participant | 相同邏輯規則，由 owning node 建立 native | root scope 的 N 與 ownership |

對 wrapper N 提出 restart 時，先解析其 current main native；回傳 requested N → execution N 的明確對應，不把 wrapper 本身說成 agy 或 codex process。

同一批選到 wrapper N 與它的 native N 時，解析後去重，只重啟一次。不同 execution N 可並行；同一 N 的 restart／設定／派工必須有單一序列。

### 2.3 什麼叫啟動完成

不是 Process.Start 成功，也不是收到一段 MessageCompleted。

完成條件全部成立：
- 新 provider、model、effort 通過驗證。
- 新 native SID 有實際協定證據。
- 新 native 已讀取本次 handover artifact，bootstrap turn 正常終止。
- generation／provider／SID／active IAgent 或 raw binding 的切換已 durable commit。
- 之後的普通訊息才可派到新 binding。

## 3. 最小 Contract 調整提案

本節是 review 草案，不在本輪修改 concepts.fsx。

### 3.1 不增加 native session vertex

保留現有 ReActEndpoint.Participant 與 FGL labelled edge 形狀。用 participant 的 typed self-edge 記錄前後 native session 關聯，不額外新增一組 session node／endpoint／routing address。

理由：N 已是穩定的邏輯節點；同一 N 可以有多條 session transition edge。歷史 SID 放在 edge，不要只覆寫 node label 後丟失舊 SID，也不要讓 /list_participant 出現多個相同 N。

建議的資料形狀如下，名稱可在 Contract review 時精修：

~~~fsharp
type NativeAgentType = string // 先接受 "agy"／"codex"，入口使用 Argu 驗證
type NativeSessionIdentity = NativeAgentType * string
type NativeSessionGeneration = int64

// 既有 case 保留供舊資料 decode；不能因名稱含 Codex 就猜 provider。
type AgentSessionId =
    | WrapperSessionId of ReActParticipantSessionId
    | NativeCodexSessionId of CodexSessionId
    | NativeAgentSessionId of agentType: NativeAgentType * sid: string
~~~

新版本原生 session 使用 NativeAgentSessionId；legacy case 只代表舊格式，需配合已存設定判斷 provider。

### 3.2 transition 是資料，不是另一個 runtime class

用一個階段 DU，加到 ReActEvent 的一種 self-edge。以下是語意草圖；正式型別的 StreamId 宣告順序須依 F# 由上到下排列。

~~~text
ParticipantRestartPhase
  Requested(transitionId, oldGeneration, targetAgentType, effectiveArguments)
  HandoverPrepared(transitionId, throughStreamId, artifactId, sha256)
  CandidateStarted(transitionId, candidateAgentType, candidateSid option, bootstrapRequestId)
  Activated(transitionId, nextGeneration, previousIdentity, currentIdentity, artifactId)
  Failed(transitionId, phaseCode, boundedErrorCode)

ReActEvent
  ParticipantRestartChanged(streamId, causedBy, phase)
~~~

- source、target 都是同一 logical participant。
- Activated edge 明確保存 previous／current provider＋SID，形成可查詢的前後 session 關聯。
- Failed 不保存 stderr／stdout 全文；只留穩定錯誤碼與診斷 correlation。
- node label 的 SessionId 仍只呈現最新 active binding；history 從 transition edges 取得。
- transition 事件視為 topology／control data：不派給模型、不當一般使用者訊息、不計入 60KiB。
- 原本「不同 SID observation 拒絕」的規則不放寬。只有 Activated 這個 CAS transition 可以更新目前 SID。
- actor path 可以因 physical rebind 改變；不能因此增加 session generation。

### 3.3 ReActLoop 是唯一操作入口

新增 RestartParticipant 語意，輸入為：
- requested participant；
- desired agent-type；
- Argu native override argument string。

回傳實際 execution participant 的最新 ReActParticipantInfo。實際型別沿用 FeasibleT／Task<Result<_,exn>>，不另造 Application／Runtime／Entry 物件。

另提供帶 generation 的 native routing 操作，讓舊 actor 的延遲輸出不能冒充新 session。舊 RouteReActDataStream 保留普通 wrapper／human routing；新 native adapter 使用 generation-aware route。

IAgent.Request、wrapper control、MCP、remote facade 都呼叫 ReActLoop member。外部不直接 tell loop handler，也不繞過 IAgent.Send 操作 participant actor。

本輪不額外發明 LINE／console 的 provider 切換字串語法；自動偵測 startup desired provider 與已保存 binding 不同，以及程式化 RestartParticipant API，是明確入口。若未來加命令語法，仍以 FAkka.Argu 和同一 member 實作。

## 4. graph 還原與一致的 context 視窗

### 4.1 recovery 必須在 native 建立之前

1. 讀取 root scope、checkpoint schema／watermark。
2. 返序列化 vertices、labels、edges，驗證 root、N 唯一性、parent／Main 關係、edge endpoints、StreamId 與 session generation。
3. 依 committed watermark replay SQL delta；只還原資料，不啟動 native。
4. 復原仍未完成的 restart phase，不能把 CandidateStarted 當作 Activated。
5. 只在完整驗證成功後發布 GraphReady。失敗不得使用空 graph 繼續啟動。

checkpoint 損毀且原 SQL journal 可完整重建時，可重建並產出新 checkpoint；未知未支援 schema／缺少必要歷史時明確失敗，不覆蓋原 checkpoint 或猜身分。

### 4.2 operational graph 與 handover view 的分工

保留現有一般 graph recovery／compact 政策。handover 使用一個有固定 cutoff H 的只讀 context view：

- 先由 root handler 取得 graph copy 與已提交的 H。
- 拷貝必要 topology／participant labels，不能只收 edges。
- 當 operational graph 的可用對話不足時，從原 SQL journal 按 StreamId keyset 倒序分頁讀取、補足該範圍的 context。
- 取得的 selected edges 依原順序放入暫時 FGL view；不把舊 events 重新 append 成新 StreamId。
- SQL query 全部限制 root session／address 與 StreamId ≤ H。不要讀整個 DB，也不要把多個 root 的本地 StreamId 當成全域序號。
- H 之後收到的新 prompt／sub result 留在既有 routing queue，handover 成功後再交付。

這個 view 是 artifact 建立時的普通區域值，不是長駐第二套 graph authority。原 graph、SQL history、compact checkpoint 不被 60KiB selection 修改。

### 4.3 participant context 的範圍

- root main：root wrapper 及其 ownership subtree 的相關業務 edges，包含 main 對 subs 的 instructions、sub 自己的可見工作輸出、回到 main 的 results。
- sub wrapper main：該 sub wrapper ownership subtree 的業務 edges，以及曾路由進／出該 subtree 的 instructions／results。
- raw sub：它自身收到、產生、回覆的業務 edges與必要 parent 資訊。
- 不把 sibling 未曾交付給這個 sub 的完整對話硬塞給它。
- participant 的 ParticipantInput／StartTurn／SteerTurn 是必要輸入，不能只選最後的 AgentEnd。
- 普通 subagent context 使用 AgentWork；原本明確 COT 的已保存可見訊息可以保留其 AgentCot 標記，但 handover 本身不是 COT。

同一 root 的 remote participant 也須將必要業務 stream 路由到 root loop；若 owning node／舊協定無法提供該範圍的必要 graph data，回報缺失，不把「root 有最後結果」冒稱為完整 participant context。

### 4.4 60KiB selection 的確切規則

60KiB = 60 × 1024 UTF-8 bytes，是文件文字大小的估算預算，不宣稱等同 token 數。

1. 先固定 H 與 scope。
2. 分類與範圍過濾，排除 StdOut／StdErr／raw process IO／topology 控制事件。
3. 對 eligible context 依 StreamId 由大到小走訪。
4. 每筆 render 後估計 UTF-8 bytes，prepend 到結果；累積約達 60KiB 就停止。
5. 輸出仍是 StreamId 正序。檔案固定 UTF-8 no BOM、LF，不依 Windows shell code page。
6. 以整筆 event／完整訊息邊界為原則，因此最後一筆允許超出約 60KiB；不切壞 JSON 或 Unicode。
7. 單筆 event 自己就超過 60KiB 時，也保留整筆並標示 overshoot，不偷偷 skip／截斷。如果實際 native 文件讀取／input 上限因此失敗，回報該 StreamId 與大小，不 Activate，也不自動換成摘要。
8. 沒有足夠 60KiB 就取全部可用 eligible context；60KiB 不是最低必須湊滿的資料量。
9. 純新 participant 可以沒有歷史；已知舊 session 卻無法還原任何必要 context，須回報 ContextUnavailable，不能假裝 fresh start 就算完成。

必要 participant／parent／session 表頭與每筆來源資訊一併估算；表頭僅列本次視窗引用及操作必需的 participants。不能因 60KiB 任意刪掉維持解讀所需的身分關係。

### 4.5 事件呈現與排除細則

每筆保留 StreamId、causedBy、source／target N、事件種類與業務內容。窗口外的 causedBy 明確標示 outside-window，不能捏造來源內容。

MessageCompleted 優先於同 messageId 的 deltas；同 producer／同 turn 的 AgentEnd 重複正文只保留一次內容並保留完成標記。相同文字、不同回合不能用全域 Distinct 去重。

若訊息只有尚未完成的 deltas，保留原次序並標示 interrupted／partial，不能將碎片當完整答案。先分類再計 bytes，不讓碎片與 final 重複耗掉預算。

之前 handover 的 bootstrap 內容不再巢狀展開成新 handover；以其 transition／artifact reference 識別，從原始業務 events 重建視窗，避免每次重啟把舊 handover.md 複製一遍。

StdOut／StdErr 的排除按 typed event／已知 payload schema 判定，不用文字 contains("stderr") 亂刪人類討論。任何 native JSON terminal、command line、process trace 也不作為聊天內容塞入 handover.md。

## 5. handover artifact 與第一筆 native 輸入

### 5.1 artifact

保存於既有 Fodex output/artifacts 的 participant 子目錄：

~~~text
participants/<N>/handover/<transition-id>/
  handover.md
  manifest.json
  assets/                 # 只有本次確實需要且可取得的附件
~~~

這是正式輸出，不放 agent scratch；也不建立新的 demo project。

manifest 保存 root／participant、舊 generation／provider／SID、新 provider、H、selected StreamIds、實際 UTF-8 bytes、content SHA-256、附件清單與 artifact schema。產生後的 handover.md 不再修改；新 SID 在啟動後記入 graph transition／manifest 的完成紀錄，不回頭改正文。

handover.md 包含：
- 這是歷史 context，而不是重新執行舊指令的要求。
- 接替的 N／who／parent／角色，舊 provider／SID、新 provider。
- context 範圍、cutoff、窗口截斷與 partial 訊息標記。
- 約 60KiB 的正序業務記錄。
- 最末專用控制區的一次性 handover-ready 驗收碼。

不包含 stdout／stderr、token／secret、Process 物件、IActorRef、quotation closure、logger 或全域 mutable registry。

### 5.2 Windows 與跨節點

60KiB 英文文字可能超出 Windows process command line 長度。禁止把整份 markdown 放入 AGY 的 -p argv。

固定採 artifact-first：
- 在 owning node materialize 檔案並核對 size／hash。
- 新 native 的第一筆 prompt 很短，只要求先完整讀取該 UTF-8 文件，且不得先執行歷史未完成工作。
- Codex exec 仍用既有 stdin；app-server 仍用既有 turn RPC；AGY 仍使用已支援的 print/json 模式與短 prompt。
- 不因這個需求切換 AGY 的 stream-json 協定，也不新增 process manager／每筆新 ActorSystem。
- remote 不能直接使用發起端的 F:/ 或 G:/ 路徑。由既有 remote control 接線傳遞 artifact ID／hash，owning node 以 bounded chunks 取得／落地，再交自己的 native。
- native 讀不到、hash 不符、path 不屬本次 artifact root：不得開始或完成 bootstrap。

### 5.3 bootstrap 完成判斷

為避免「只把 path 給模型，模型未讀卻回 READY」：
- 驗收碼只存在 artifact 最末控制區，不放進短 bootstrap prompt。
- short prompt 要求讀完後回傳該碼一行；不強迫模型生成額外 JSON schema。
- 除正常終止與真實 SID 外，還需最終答案精確符合本次碼。
- 這證明檔案內容可達且曾被讀取，不宣稱證明模型記住每個 bit。
- 未收到碼、收到舊碼、只收到 MessageCompleted 尚無 AgentEnd、native exit 非成功：都不 Activate。
- bootstrap 的生成是 AgentWork，目的地為控制 owner；不冒充 AgentCot，也不回 LINE 當使用者答案。
- 驗收碼不是服務密碼；它只防止誤認別次 handover，不代替原有控制權限。

### 5.4 圖片／附件的邊界

graph 裡的本機路徑可能已被 v3 turn cleanup 刪除，capability URL 也可能已到期。不能把路徑字串交給新 agent 就宣稱圖片已 handover。

本次視窗引用、且仍有可用來源的必要附件，應複製到 artifact-owned assets，核對 hash，使用 owning node 的新本機路徑。文字檔不塞圖片 base64。

若必要附件已不可取得，preflight 明確列出缺少的附件與相關 StreamId，不假造像素、不靜默改成「文字足夠」。讓操作者補回附件或明確縮減本次 handover 範圍後再做。不能因單一附件缺失自動刪舊 SID／歷史。

這也表示：本機 CLI／graph 原來沒記錄的 native 私有 context 不可能憑空重建。本輪承諾的是 graph 中可觀測業務資料的最新約 60KiB 與其可驗證附件，不匯出 provider 隱藏推理或未保存的全部 tool transcript。

## 6. agent-type 改變的完整流程

### Phase A：辨識與預檢，尚未中斷舊 participant

1. 從 graph／已持久化設定讀取舊 provider、SID、generation；不可先用新 startup defaults 覆寫它們。
2. 將 desired args 經 Argu 正規化，解析出新 provider、adapter、model、effort。
3. provider 相同且只是重綁：保留既有 resume 路徑。
4. provider 不同：建立唯一 transition ID，走 fresh＋handover；將舊 provider 的 resume 參數從 candidate args 移除。
5. 驗證目標 model／effort、capability、native executable、artifact 存放與遠端協定。AGY high model 不可搭 low。
6. 驗證 graph 可恢復、context scope 與附件可用。preflight 失敗保持舊 participant，不動 binding。

### Phase B：target barrier 與固定 H

1. 單一 execution N 只容許一個 restart；重複相同 transition 回原狀態，不另建 native。
2. wrapper／hub 對此 N 停止「實際派送」，新工作進原本有界 queue；不暫停不相關 participant。
3. cancel 舊 native 的當前 turn，等待取消／process cleanup 證據，保存 interruption 結果。
4. 不自動重送剛被取消、是否有副作用未知的舊工作。
5. 等舊 turn 的可接受終止資料已提交後取得 H／graph copy，記錄 Requested。
6. H 之後的新輸入／result 不倒灌進同一 artifact。

### Phase C：建立 handover

1. 由固定 H 的 graph／SQL view 選取約 60KiB。
2. 排除 stdout／stderr 等不允許內容。
3. 原子寫入 artifact，核對 strict UTF-8、size、hash；記錄 HandoverPrepared。
4. 不呼叫 COT／摘要模型，不 prune graph。

### Phase D：建立 candidate 與優先交接

1. 使用同一 N、新 generation 的 candidate resource；尚不取代 current binding。
2. 新 provider 建 fresh session，絕不傳舊 provider SID。
3. 第一筆 native input 只能是 handover bootstrap。hub orders／使用者 prompt 仍在 queue。
4. 啟動前先 durable 記錄 CandidateStarted；尚無真實 SID 時填 None，絕不借用舊 provider SID。
5. AGY print mode 必須等成功 terminal 回傳 conversation_id 後，才記錄 Some 新 SID；Codex app-server 可較早觀察 thread.id，但仍只是 candidate。
6. 等原生成功 terminal、對應新 SID 與本次 handover-ready 驗收碼，全部確認才進 Phase E。

### Phase E：原子 Activate

在 root handler 的單一 transition／SQL CAS 中確認：
- current generation 仍是預期舊值；
- transition ID、cutoff／artifact hash、candidate SID 都吻合；
- 沒有 competing restart 或停止要求撤銷這次 transition。

同一 durable batch／transaction：
- append Activated self-edge，保存 previous → current 身分；
- 更新 active native SID／provider／generation 的 SQL projection；
- 更新 participant label／有效設定；
- 保留 N、who、wrapper SID、parent 與 Main 關係。

commit 成功後才換 current IAgent／raw binding。queue 仍受本 transition 的 ready gate 保護，直到 Phase F 確認舊資源清理；不能把「binding 已提交」與「啟動完全完成」混為一談。

### Phase F：舊資源與 checkpoint

- 確認舊 actor／native process 已退出，或記錄仍需 retry 的 cleanup，不能留 orphan。
- cleanup 確認後才釋放 queue，依原順序交付 H 之後的新工作，回報 ready。cleanup 失敗不回 Ok。
- 若 Activated 已提交卻 cleanup／ACK 失敗，保留新 active SID；同一 N 的下次同參數操作先恢復這個未完成 transition，只重試 cleanup／回覆，不再執行 bootstrap 或另建第三個 session。
- checkpoint 保存含舊／新 session transition 的 graph。
- raw native IO 留在既有獨立 trace；不混入 agent context。
- 新 SID 可透過 GetSessionId／list 查到；舊 SID 仍可從 graph transition 查到。

## 7. 崩潰、失敗與恢復

| 發生點 | 必須行為 |
|---|---|
| Requested 前 | 舊 participant 仍可用；不建立 candidate |
| 取消舊 turn 後、artifact 前 | 舊 SID／binding／歷史保留；狀態 truthful，不假稱它仍在生成 |
| artifact 完成、native 未建 | 可用同一 immutable artifact／transition 繼續 |
| native 建好、bootstrap 完成與否未知 | 若有可驗證 provider terminal／驗收碼則繼續；否則標 indeterminate，不盲目重送 bootstrap 或另建第三個 session |
| bootstrap 成功、Activate 前 | 同一 candidate 與 transition 重試 CAS；不再生成 handover |
| Activate 已提交、ACK 遺失 | 重新讀 graph／SQL current generation，回已完成結果；不重啟第二次 |
| candidate cleanup 失敗 | 保留 resource／transition 供重試，不清 owner、不聲稱停止成功 |
|舊 actor 延遲輸出 | generation 不符便拒絕更新新 context／完成新 turn，診斷留獨立 log |
| native 回不同 SID | 保留 expected／candidate 身分，不把錯 SID 寫入 active SQL |
| remote 斷線 | owner／artifact／SID 保留；新連線查同 transition，不以新 N 冒充恢復 |

普通失敗不自動切回並重跑舊業務指令；若要恢復舊 provider，仍使用其正確舊設定與 SID，由明確控制操作觸發。

### 9.3 artifact／native transport／跨節點

- artifact hash、UTF-8、immutable file、ReadyToken 未出現在 short prompt。
- 用至少 60KiB 的純英文 context，證明 Windows argv 保持短字串；內容由 artifact 讀入，未觸發 command line limit。
- exec 的 stdin／EOF與JSON terminal、app-server RPC、AGY json terminal維持各自正確協定。
- 新 session 第一筆必為bootstrap；第一個業務prompt是bootstrap之後的下一筆。
- remote artifact在owning node落地，不能偷用測試機共享路徑；錯owner／hash／舊generation拒絕。
- restart每個durable phase後重開process，分別驗證復原；未知native完成狀態不得自動再生成。

provider／角色矩陣：
- root main：Codex app-server→AGY、Codex exec→AGY、AGY→Codex app-server、AGY→Codex exec。
- sub wrapper main：同上四種。
- raw sub：Codex exec→AGY、AGY→Codex exec。
- 上述10種先用真actor／SQL＋可控native fixture自動測；remote再驗同樣邏輯。main仍是wrapper，不發明raw main模式。
- live代表性案例需涵蓋兩個方向、main/sub wrapper/raw與兩個Codex adapter；fixture通過不冒充真模型通過。

live handover 測試的做法：
1. 舊provider透過真正wrapper／hub收到一個隨機內容與未完成的小任務，並完成至少一輪；不同participant內容不同。
2. 重啟服務／loop後，只讓API指向原root/N，不把答案重新塞給新participant。
3. 切換provider，核對native第一筆讀取handover。
4. 新provider對舊圖／文字與自身被派工作作正確接續；從MD／native inputs／terminal／graph對照，而非只看一句READY。
5. N／who／parent原封不動；新SID不同；graph仍可查舊SID。
6. LINE另外做「圖→文字→圖」：只收到agent答覆，無輸入圖echo；三筆各有route、無漏件／重複／跨圖。
