## 6. SQL 與恢復語意

### 6.1 cache

- 固定 scope `cace0000-1114-4000-8000-000000000001`，不是每 root 一份 CD／KV。
- journal／KV／revision／operation receipt 同交易，SQL 成功才改 graph／回 ACK。
- 寫操作相同 operationId＋相同 payload 回原 receipt；不同 payload 拒絕。delete 留 tombstone，重建有新 revision。
- key 保留大小寫／Ordinal 意圖，**尾端 whitespace 拒絕**。這是使用者選定的規格修訂：SQL BIN2 仍會把 `k` 與 `k ` 視為相等，因此不能假裝任意尾空白可區分，也不自動 Trim。
- cache scope 恢復完整狀態，不被普通對話最近一小時 graph tail 規則剪掉。關閉普通 wrapper 不清 cache。

### 6.2 LINE 名冊／control／batch

- Topic 比較 Trim→NFC→UpperInvariant，顯示保留原名；同 conversation 唯一，跨 conversation 可同名。
- newagent 依 creation route reserve 原 WSID／argv，未知 create 結果不另生 SID，不自動 select。
- drop 先 Dropping、停止新接納／取消未送批次；close 確認後才 tombstone／釋放 Topic；新建同名必須新 WSID。
- 舊 mapping 缺 provider／argv 時標 MigrationAmbiguous；service native_info 查證成功才轉可 attach，不猜 provider。
- 控制 route 自己有 SQL lease／frozen root，不排在幾分鐘 generation 的尾端。
- batches／items 保存原 route、payload hash、messageId、sender、穩定序號。`dueAt=min(first+10s,last+3s)`，限32件／256KiB文字；duplicate 不延後 timer。
- Sealed 固定 membership／ReplyRouteId／BatchId；Sending／ACK unknown 只收原 requestId 結果，不重送 generation。
- 完成時 batch／所有 member 的 Reply或Ignore／cursor 同交易；只最後 accepted member 回完整結果。
- 模型清單全部先入 `LineFodexV3ControlPages`；取頁 claim 不刪資料，同 route 重試回同頁。新的查詢不覆蓋舊查詢未取的頁。

上述是目前Legacy接線與局部能力。新RN協定還需要統一Admit receipt、BindingCommitted、可恢復root control barrier、純ReadResult與獨立delivery ledger。**現有outer Task不等於完整BindingCommitted；native OutputCursor／DeliveredStreamId不等於LINE已交付。** 失效LINE Reply能否由/next恢復，不能只憑SQL存有Result宣告完成；00292 review指正後，這些列為RN＋v3聯合gate。已驗證的/next目錄分頁，與尚未驗證的失敗native結果交付恢復分開計算。

### 6.3 最後回歸發現的獨立SQL lease問題

SDK／Core均與正式入口相同時，原control retry測試偶爾在Dispose後立即Acquire得到v3-control-in-progress。connect已是Pooling=false；因此不是「改成不pooling」即可修好，而是client關socket並不等於server已確認Session applock釋放。

OwnedSqlConnection現在由control／conversation／wrapper／runtime-cleanup acquirer傳入明確resource名；同一async gate內await sp_releaseapplock ACK，再關socket。失敗仍關socket，原錯誤與cleanup錯誤保留。新測試使用pooled連線及另一個非pooled observer，驗APPLOCK_TEST立即可取得；原assertion未放寬。

新增測試第一次ownership assertion已通過，但cleanup使用已Dispose連線作ClearPool identity，造成專屬fixture DB未刪；改以獨立pool identity清理後15/15，完整integration48/48。該次僅由本案建立的GUID測試庫在確認沒有active session後清除，未動正式Fodex資料庫。

## 7. Model／SID 政策與已確認的例外

1. model+effort 一次 fresh validation，錯誤先於 cancel／apply／persist，不能只成功一半。
2. AGY 首次 active generation 尚未回真 SID：**立即拒絕變更並保留原工作**；不等 SID 出現後暗中套用，也不改用另一家 SID。
3. idle／cold 只更新 next-turn 設定，不為改設定啟動 generation。
4. 已知 SID 的 active 變更走 owner 的 cancel／apply pair／persist／一次 continuation；raw 與 wrapper 路徑一致。
5. AGY CLI 的總體 effort 值不等於逐模型支援證據；preset model 還有配對限制。例如 flash-high＋medium 被拒絕，flash-medium＋medium 成功。
6. 本機舊 root `2d9d5f06-4a68-4b03-808d-4f651caa13fd` 實查缺 persisted native argv，native_info 拒絕 MigrationAmbiguous。沒有拿預設 AGY 模型／新 SID 冒充恢復；舊 history 留存。
